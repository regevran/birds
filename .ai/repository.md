# Repository

## Layout

```text
birds/
  .ai/                    durable context (start at README.md)
  TODO.md                 actionable work
  CMakeLists.txt          top-level build entry point
  CMakePresets.json       Ninja presets and workflows
  build/                  disposable build tree (ignored)
  data/
    src/pipeline/         default offline build steps
    src/oneoff/           manual fetch/upgrade/maintenance scripts
    in/                   sources and frozen snapshots
    out/                  installed final data (committed)
  book/
    src/                  book builders
    data/                 text.md, assets, reports
    out/                  installed PDFs (ignored)
  learn/
    src/trainer/          Python CLI: foundation/, cards/, cli.py
    src/tests/            Python tests
    cloudflare/           progress Worker: src/core.js, src/app.js,
                          src/trainer/, Node tests, wrangler.toml
    design/               browser UI design mocks (design only)
    web/                  browser client: index.html, src/app.js, assets
    tools/                account provisioning, dev tokens, image build/upload
    data/                 placeholder; progress is not stored locally
```

- `data/in` is the source of truth; `data/out` is the committed consumer
  contract. Both `book/` and `learn/` read only `data/out`.
- `build/` is disposable and holds all artifacts. `book/out/` is the installed
  book output. `learn/` has no `out`; it runs from `learn/src`.
- Progress lives in private Cloudflare R2 behind `learn/cloudflare/`; there is
  no local progress store. The browser client is `learn/web/`: served on
  `http://localhost:8001` against the local Worker, it renders Worker JSON and
  holds the token in `localStorage['birds.token']`. The L card and thin
  functional E/R/C/F answer forms render Worker views; the faces are unstyled
  until the design pass. Bird illustrations come
  from the Worker's public `/media/...` route; the footer carries the CC BY
  credit. The local dev token is generated by `learn-web-token` (signed with
  `.dev.vars`; development only).
  Design is `.ai/learn-ui.md`, with visual options in `learn/design/`.
- `.ai/` is the durable AI context described in `.ai/README.md`.

## Data contract

- `data/out/israel_birds_final.json` — 565 species. Fields include `latin`,
  `genus`, `epithet`, `english`, `family`, `family_order`, `family_he`,
  `order`, `status`, `hebrew` and `flags`. `family_order` is 1..84 by first
  appearance in the source checklist.
- `data/out/etymology.json` — `elements`, `splits`, `whole_names`, `themes`.
- The pipeline validates coverage and reassembly before installing.
- Trainer-relevant data facts (no-Hebrew species, shared Hebrew names, split
  coverage) are in `learn-reference.md`.

## Build

```sh
cmake --preset default
cmake --build build
cmake --build build --target data-build
cmake --build build --target data-install
cmake --build build --target data-test
cmake --build build --target book-build
cmake --build build --target book-one-file
cmake --build build --target book-install
cmake --build build --target learn-test
cmake --build build --target learn-worker-test
cmake --build build --target learn-worker-users-upload
cmake --build build --target learn-worker-users-deploy
cmake --build build --target learn-run
cmake --build build --target learn-web-build
cmake --build build --target learn-web-illustrations
cmake --build build --target learn-web-illustrations-upload-local
cmake --build build --target learn-web-illustrations-upload-remote
cmake --build build --target learn-web-token
cmake --build build --target learn-web-serve
```

Workflows and help:

```sh
cmake --workflow --preset data
cmake --workflow --preset book
cmake --build --preset help
```

CMake is the only supported build interface. Book-specific dependencies and
preview targets are in `book-reference.md`; Worker deployment is in
`learn-cloudflare.md`.
